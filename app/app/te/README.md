# Electrical panel editor

The French editor is available at `/te`, linked from the home navigation and room menu. When shared storage is configured, it synchronizes one public project across devices through the application server. See [shared storage setup](SHARED-STORAGE.md) for Vercel activation. Without storage credentials it retains the browser-local workflow.

## Behavior

- Circuits belong to one house-wide inventory, shown regardless of the active electrical panel. Device selectors in either panel use that list and prevent a circuit from being assigned twice across the project. Summary badges identify the assigned panel and device. Circuit creation, editing, duplication, ordering and deletion affect the general inventory; deleting the secondary enclosure retains its circuits.
- Schema 2 saves with `sharedCircuits: true` store circuits at the root and an empty nested circuit array. Earlier panel-local saves/imports are validated and migrated once: normalized equivalent names/usage/room/floor are deduplicated, missing descriptive cable/load values are filled, and all device references are remapped. Conflicting technical values and separately assigned circuits remain distinct. Intentional named copies are retained. IDs that previously collided between panels receive a deterministic unique ID. Migration never edits the original imported file.
- The GTL studio uses separate draggable illustrations and clickable detail titles, with a right-hand inspector for kit/accessory information and actual electrical-panel dimensions. Kits drop into an empty lane; electrical and communication cabinets and matching accessories drop onto existing GTLs. Mounted items can move between GTLs. A separate × unmounts a cabinet while keeping its circuits/devices; removal is undoable. Mouse, long-press touch and keyboard sensors share type-filtered collision detection. Dropping the first kit on either empty lane creates the first valid unit; no sparse arrays are saved. Removing a GTL clears its cabinet placements. The optional second electrical panel can share a GTL with the primary panel.
- The first TE step configures one or two shared Schneider Resi9 GTLs side by side. Each GTL can use R9HKT13 (13 modules) or R9HKT18 (18 modules), have a bounded list of matching accessories, and receive the primary/optional secondary electrical panels and an enabled communication cabinet through explicit placement controls. The diagram is an installation-planning aid, not a dimensioned mounting drawing. The saved model preserves older single-GTL projects by upgrading them to one GTL unit; GTL accessories become explicit material lines and need installation confirmation. GTLs occupy no DIN slots.
- Add a second electrical panel in the same project. Both enclosures appear side by side on desktop and stack below 1000 px. Each has independent dimensions, rows, devices, circuits, and accessories; select a panel or one of its devices to target the shared catalog and inspector. Catalog drops work on either enclosure; moving an existing device is restricted to its own panel to preserve circuit/protection relationships.
- The optional `secondPanel` field contains one validated panel and cannot contain another panel or a communication cabinet. Existing schema 1/2 projects remain supported. Both panels share autosave, JSON import/export, undo/redo, aggregate material quantities/CSV and checks. Communication belongs to the common project. Print includes both compositions and circuit records, including the inactive panel. Removing the second panel requires confirmation and is undoable.
- Start with an empty three-row, 13-module enclosure. Choose 1–6 rows and either 13 or 18 modules per row. Checked references are automatically identified for three- and four-row enclosures with 13 or 18 modules per row; other configurations remain provisional.
- Drag equipment from the catalog, move it between fixed positions, or use the accessible Add and Move controls. Mouse, long-press touch, and keyboard sensors come from `@dnd-kit/core`.
- The catalog row selector has been removed. Device catalog + buttons and the distribution inspector's Add button use the active row (the first row by default); clicking or focusing inside a row activates its panel/row and highlights its border. Selecting or placing a distribution also activates its row. Dragging still uses the actual drop position.
- Each circuit belongs to at most one breaker. Upstream differential relationships are explicit and remain attached when devices move. Removing a differential clears affected upstream assignments.
- Undo/redo retains the last 50 project edits during the session. Reload restores the project, not its undo history.
- Each row independently supports multiple XE distributors or XP combs at explicit module positions. In the Distribution catalog filter (or the collapsed distributors section under Tous), drag a reference onto the compact band above the breakers. Drag a placed segment to reposition it or move it to another row within the same panel; the grab offset is preserved. Each segment has a separate × removal button. Row forms/selectors are removed. The distribution detail sheet offers a text-only Add button for the first gap in the active panel/row; focused placed segments support left/right arrows for single-module movement and Delete/Backspace for removal. Mouse and long-press touch drags show green/red placement previews. For example, 5 + 8 fills a 13-module row; 5 + 5 + 8 fills an 18-module row. The current minimum catalog length is five modules, so at most three segments fit. Coverage occupies no additional rail slots and does not represent electrical connections. Overlap and overflow are blocked; removing a row or shrinking the enclosure requires moving/removing affected distributions first.
- Material quantities include the enclosure, placed devices, selected distributors, and manually entered accessories. Indicative Elec44 unit prices and totals including tax are displayed where verified. Assembly information remains subject to verification; no compliance certification is generated.
- Print includes the panel, circuit labels, material list, assumptions, and outstanding checks, regardless of the currently selected dossier view. CSV exports material quantities; JSON exports the complete editable project.

## Supplier pricing

- `data/elec44-prices.json`, `data/123elec-prices.json` and `data/elecdirect-prices.json` are static EUR/TTC snapshots with exact retailer links. Snapshot dates can be overridden per item for incremental updates. Elecdirect has 43/48 verified catalog references as of 2026-10-25, covering devices, distributions, 1–4-row enclosures, both GTLs and five accessories. No substitute-reference prices are used. The interface and CSV show all three suppliers separately; the comparison uses only lines priced by all three for fair like-for-like totals. Missing prices remain explicit and are excluded from each supplier's known subtotal.
- Refresh Elecdirect with `node scripts/update-elecdirect-prices.mjs YYYY-MM-DD` from `app/`. The configured exact product pages must pass SKU, non-pack, currency, gross/net VAT and structured-offer checks before a new snapshot is written. Sources are maintained in `data/elecdirect-sources.json`; unconfigured references stay unpriced. No prices are fetched at runtime.
- Catalog cards, distribution cards and the device inspector show unit prices linked to the corresponding Elec44 product page. A shared budget covers both panels and common GTL; the material table shows quantity × unit price and a total. If any items are unpriced, the figure is labeled known subtotal and the unpriced quantity is shown. Manual/generic equipment without a matched reference is not treated as free. Prices exclude delivery, loyalty benefits and pack discounts; date and indicative status are visible. The application does not fetch prices at runtime.
- `lib/pricing.ts` calculates totals in integer cents and generates the material CSV with unit/line prices, coverage status, source URL, date and a total row. Unknown prices export as empty numeric cells and explicit Non chiffré status. Print includes prices/budget. JSON remains a project-design export; it does not embed or trust imported prices, and saved equipment/custom labels remain unchanged.
- `data/elec44-sources.json` records the discovered exact product URLs. Some retailer slugs contain historical reference/rating errors: verification uses product reference and structured SKU, not URL text. To refresh explicitly, run `node scripts/update-elec44-prices.mjs YYYY-MM-DD` from `app/`, after confirming new/missing source URLs. The script retrieves at most four pages concurrently and writes the snapshot only after all configured sources pass exact SCH-prefixed reference, EUR, non-pack and tax/price checks. It checks product gross price against net + 20% VAT and the structured Offer; search/browser-reader excerpts sometimes show net amounts under TTC labels. Malformed trailing review text in retailer JSON-LD is discarded before parsing the pricing fields. Network or verification failure preserves the existing snapshot. Missing source entries stay unpriced.
- `tests/pricing.spec.ts` verifies cent arithmetic, aggregated quantities across both panels/GTL, unpriced items, CSV/source/date and spreadsheet-formula escaping, plus catalog/inspector/material/print/mobile rendering. Existing editor/distribution regressions also passed; the known device mouse-drag regression remains excluded.

## Persistence and validation

`lib/model.ts` owns the versioned schema, placement validation, enclosure resizing, material quantities, checks, and history reducer. `data/catalog.ts` owns immutable product data. `components/panel-editor.tsx` owns browser interactions; the route shell supplies metadata.

The localStorage key is `maison1973.electrical-panel.v1`. Restoration completes before autosave starts. The shared project is read once when the page opens; local edits are saved locally and replace the shared project after a 500 ms debounce, with no polling or focus-based refresh. `lib/use-shared-project.ts` owns restoration and saving; `/api/te/project` validates writes and atomically increments the Neon PostgreSQL record revision. Unreadable or incompatible saved data suspends saving until the user explicitly authorizes replacement. Storage failures leave editing and JSON export available.

Positioned distributions use the optional `row.distributions` array of `{id, reference, slot}` (zero-based slot; up to three entries with unique IDs per row). Edited rows clear the legacy `row.distributor` string; an older row without the array is interpreted as a single distribution at position 1, preserving its saved representation until edited. Imports reject ambiguous rows containing both a nonempty legacy reference and the new array, unknown references, invalid slots, overlaps and overflow. Schema/catalog versions and storage key remain unchanged. Both panels include every segment in undo/redo, JSON, autosave, material quantities, CSV and print. Repeated references aggregate by quantity.

Checks use the actual segment intervals: devices in gaps or spanning a boundary are flagged, and XE/XP compatibility messages apply only to devices intersecting that segment. Multiple segments prompt for separate feed/protection design; adjacency never creates automatic electrical links. `components/row-distribution.tsx` owns draggable catalog entries, per-slot drop targets, compact draggable segments and removal buttons. `panel-editor.tsx` filters collision targets by drag type so distribution drops and device drops stay separate, and handles validated placement/moves including legacy rows. Printed tracks retain references/positions and hide removal controls.

Distribution catalog cards use the device/differential visual layout: illustration beside the title, connector description, reference and linked price. The catalog has no + button or grip glyph; the illustration remains draggable. Click the illustration/title to preview its detail sheet, or click a placed segment to inspect that instance in the shared right-hand panel. Catalog previews offer a text-only “Ajouter à la rangée active” button for non-drag addition. Enter selects without starting a drag; Space retains the drag sensor behavior. `components/distribution-details.tsx` shows an illustration, family/reference, linked Elec44 unit price, nominal width, XE connector state, Schneider product link and (when placed) panel/row/occupied positions and removal. Selection uses panel/row/segment IDs so repeated references remain independent; it resolves current data after changes, follows successful moves and clears when removed or when a device/another panel is selected. The selected segment is outlined and exposes `aria-pressed`. No per-row forms or persistence fields are added for the detail sheet.

`components/distribution-illustration.tsx` supplies lightweight schematic SVG drawings for the distribution catalog, placed segments and drag previews. XE illustrations show socket bars and an optional horizontal screw-terminal block centered above the bar, leaving the entire contact row visible; XP combs use copper-colored teeth. The drawings use landscape proportions, with catalog image space of 78 × 38 px. Catalog illustrations identify each product family; module counts are labeled explicitly. A visual legend distinguishes these families and shows a 5+8=13 row example. The UI explicitly labels these as simplified illustrations: they identify product families, not actual terminal geometry, connections or an installation method. SVGs are decorative (`aria-hidden`); reference/type text and accessible button labels remain intact.

The optional root `gtl` field stores one or two GTL units, their references, quantities, matching accessories, and primary/secondary/communication-cabinet placements. Older single-reference GTL projects are accepted and normalized to one unit. The configuration participates in undo/redo, autosave and validated JSON import/export; nested GTL entries in the second panel are rejected because this equipment belongs to the common project. Disabling the GTL removes the configuration and its material quantities.

Imports are limited to 1 MB and validated for supported schema/catalog versions, field lengths, bounded collections, known references, unique IDs, valid geometry, and valid circuit/protection relationships. Invalid imports preserve the current project. Valid imports require replacement confirmation and are undoable. Unknown catalog versions are rejected rather than silently reinterpreted. Imports cannot supply catalog source URLs.

The catalog version identifies the dimensions and product attributes used by a project. Any incompatible future catalog change must increment it and either provide a migration or continue rejecting old files explicitly.

## Impulse relays

The `impulse` category includes R9PCL216 (16 A, 2NO) and R9PCL2S (silent, 16 A, 1NO), both Resi9 XP TL units with 230 V AC control and one 18 mm slot. Product identities are linked to Schneider's catalog; dimensions and control ratings come from Schneider-authored technical sheets. These screw-terminal devices are not labeled as XE plug-on equipment. The editor supports placement, variant changes, labels, persistence and materials. It does not model control wiring or circuit associations for these devices; label the controlled lighting circuit and retain its breaker separately. Relay references cannot serve as upstream differential protection. Additive entries preserve the catalog version and saved projects.

## Communication cabinet

An optional section below the electrical editor plans the communication cabinet independently from electrical DIN rows. Enable it to enter a cabinet reference, location, network grade/category, optical or copper termination, Internet box, switch port count (0–48), and up to 48 RJ45 destinations with room and label. These are generic planning entries without a preselected manufacturer or certified assembly. RJ45 material quantities represent complete links to equip, not a verified bill of individual connectors or cables.

The optional validated `communication` field in schema 2 preserves existing schema 1/2 imports. Cabinet edits use the existing project history and persistence, and appear in JSON, material CSV and print output. Disabling the section retains its configuration while omitting its equipment from material quantities. Browser coverage checks mobile editing, restoration, JSON export, materials, printing and undo; model tests reject invalid counts, booleans and duplicate port IDs.

## Circuit associations

The inspector exposes an optional second circuit for references allowed by `supportsTwoDepartures` (2–20 A). Both circuit associations are shown on the board and in circuit records, saved and exported, and cleared independently when a circuit is deleted. Schema 2 imports schema 1 projects without losing existing associations. A circuit cannot be assigned twice, including on the same breaker. The existing model restriction keeps the 32 A reference at one assignment. These relationships describe planning data and do not establish electrical suitability.

## Verification

Run from `app/`:

```sh
npm run lint
npm run build
npx playwright install chromium
npm test
```

The Playwright configuration starts a production server on dedicated port 3197 and stops it after testing. Build before running browser tests; existing unrelated development servers are never reused. `npm run test:model` and `npm run test:e2e` select the model or browser suites. The model suite currently uses the same test runner/server configuration.

The 26 electrical model/browser tests cover geometry, widths, resizing, import rejection, relationship cleanup, history, material quantities, actual mouse/touch moves, keyboard cancellation, accessible placement controls, reload persistence, JSON export/import, printing visibility, corrupt storage, quota failures, mobile overflow, communication cabinet editing, surge protector placement, impulse relay variants, and home navigation. After adding impulse relays, build and lint passed and 25 tests passed with the previously failing mouse drag scenario excluded. Native PDF pagination and real electrical compatibility are outside automated validation.
